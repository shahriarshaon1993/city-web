# Decisions log (wins over docs/spec and docs/design)

Format: `DEC-NN (date, phase) — decision. Why. Affects: …` Keep each entry ≤ 4 lines.
Spec-time decisions DEC-01…25 and open items OPEN-01…04 live in `spec/decisions.md`; build decisions continue here from DEC-26.

- **DEC-26 (2026-10-25, plan) — No automated test suite.** Everything REQUIREMENT §14 calls a test (QA-UNIT/FEAT/SEC/E2E/A11Y/SEO/PERF), the CI gates of DEP-CI-01, "asserted in tests" in SEO-PERF-014 and the CI render of QA-SEO-03 are replaced by each card's manual **Test** checklist plus the checks in `CLAUDE.md`. Starter-kit tests stay untouched; they are deleted (with the owner's approval) only when the feature they cover is removed. Why: solo developer, time. Overrides AGENTS.md "Test Enforcement".
- **DEC-27 (2026-10-25, plan) — No CI test pipeline.** The owner removed `.github/workflows/tests.yml`. GitHub Actions is used only for the snapshot renderer (19.3), deploy (20.1) and the off-site backup pull (NFR-BAK-01); none of them runs tests or lint. `.github/dependabot.yml` stays until the owner decides otherwise.
- **DEC-28 (2026-10-25, plan) — Starter kit = official Laravel 13 Vue starter kit** (Fortify, Wayfinder, Inertia v3, TypeScript, shadcn-vue/reka-ui, Vite+ `vp`). Accepted differences from §12.1: **Wayfinder replaces Ziggy** (ARC-007 URL generation and the `ziggy` shared prop of ARC-003 / volatile key of SEO-REN-03 are dropped); Vite+ is the build tool instead of plain Vite 8.3.5; TypeScript and `@vueuse/core` stay at the installed versions unless the owner approves a bump. Exact versions are recorded in a card's Done notes when a package is added. Starter extras: 2FA kept (ADM-AUTH-002); self-registration removed in 10.1 (ADM-AUTH-006); appearance/dark mode only in the admin (the public site has no dark toggle, DESIGN §2.3).
- **DEC-29 (2026-10-25, plan; confirmed by the owner in 0.1) — Frontend first, props-first demo data.** The owner wants the client to review the whole public frontend before the backend. In Part A (phases 0–9) real routes and controllers render pages whose props come from `App\Support\Demo\DemoContent`, shaped exactly like the later API Resources (ARC-002) and typed in `resources/js/types`. Request-level rules are built for real in Part A: URL normalisation, single-facet redirects, noindex/canonical, Form Request validation. Part B swaps the data source per entity (12.1, 13.3, 16.x, 17.x) without touching Vue components; `DemoContent` is deleted in 16.4. Why: no rework when the backend lands.
- **DEC-30 (2026-10-25, plan) — Docs consolidation.** `REQUIREMENT.md` and `DESIGN.md` (v1.0.0) were split into `docs/spec/*` and `docs/design/*` by a scripted line-range copy (text verbatim, IDs unchanged). The coverage check confirmed that every non-blank, non-separator line was placed exactly once. Only the two document titles, `---` separators and blank lines were dropped. `CLAUDE.md` maps every original `§` to its new file. After the owner's review the originals are deleted from the working tree; they stay in git history (they must be committed first). Never read them again.
- **DEC-31 (2026-10-25, plan; confirmed by the owner in 0.3) — Demo images mirror the media conversions.** `php artisan demo:images` (PHP GD, no new package) writes demo photos with the widths, formats and file names of CMS-MED-005 / HERO-011 and emits the `MediaImage` prop shape. 11.1's media resource must output exactly the same shape, so `ResponsiveImage` and every page stay unchanged when the media library arrives. The command is deleted with `DemoContent` (16.4).
- **DEC-32 (2026-10-25, plan) — Action Pattern for all application logic (owner's requirement).** Every write or business operation (create/update/publish/schedule/archive, submit lead, assign, change status, import, export, convert media, generate sitemap, request snapshot…) is one `final` class `app/Actions/{Domain}/{VerbNoun}.php` (e.g. `Projects/PublishProject`, `Leads/SubmitLead`, `Media/GenerateConversions`). Each has a single public `handle()` with typed parameters and return, dependencies injected through the constructor, resolved from the container; it owns its transaction and activity-log entry. No package (plain classes, like the Fortify actions). Controllers (ARC-001), jobs, listeners, console commands, schedulers and Fortify callbacks only orchestrate: authorise → validate (Form Request) → call an Action → respond. Actions call other Actions, never controllers. Read side stays as the spec says: Query classes (`app/Queries`, list/search reads), API Resources (prop shaping) and `app/Services` (SEO, SSR, block data loaders). Affects: every card from 0.3 on; overrides ARC-001's "Action/Query" wording only by making Actions mandatory.
- **DEC-33 (2026-10-25, plan) — CRUD/UX rulebook `spec/crud.md` (owner: "fully user-friendly, smooth, proper toasts, soft delete, recycle bin").** New rule groups CRUD-, DEL-, TOAST-, VAL-, HELP- and an entity matrix; they win over the spec where they differ. Main additions: soft deletes extended to testimonials, partners, faqs, offices, amenities, post_categories and redirects; a Recycle bin screen with restore / delete forever and auto-delete (365 d leads, applications, subscribers · 30 d media · 90 d others · users never); delete guards instead of orphaned data; one-toast-per-mutation with Undo; validation defaults where the spec is silent; a dashboard "Getting started" checklist. Also new: a manual **"New lead"** in the admin (lead type `manual`, `answers.channel` ∈ phone_call / walk_in / email / event / other, `source_url` = the admin screen, `consent_text` = "Recorded by {user} ({channel})"). It serves phone and walk-in enquiries, which the spec only covered through import. The shared toolkit is built once in card 10.4.
- **DEC-34 (2026-10-25, plan) — Every admin list uses one `DataTable` built on `@tanstack/vue-table`** (headless, server-side mode) with shadcn-vue `Table` primitives (CMP-ADM-TABLE), including the media list view, the leads table, the Recycle bin and the activity log. Version per DEC-11 (8.21.3). Card 10.3 re-checks whether v9 is the better pick at that time and asks the owner before installing.
- **DEC-35 (2026-10-25, 0.1) — Fonts via the `laravel-vite-plugin` fonts helper, not `@fontsource-variable/*`.** The helper downloads Manrope 700/800 and Inter 400–600 (static WOFF2, Latin) from Bunny at build time and serves them from `/build/assets`, so browsers never contact a third-party host; preloads Manrope 700 + Inter 400; `fontaine` 0.8.2 makes the fallback faces. Overrides design/foundations.md §3.1 delivery and the "Manrope Variable"/"Inter Variable" family names in §13: tokens use `var(--font-manrope)` / `var(--font-inter)`. Why: no extra packages, same SEO-PERF-007 result.
- **DEC-36 (2026-10-25, 0.2) — Token additions and control states beyond §13.** Added `--primary-hover`/`--brand-accent-hover` (light teal-700/coral-700 per CMP-BTN-01; dark teal-200/coral-300), Tailwind colours for the success/warning/error/info scale steps used by badges, containers in `@theme static` (`max-w-content|wide|narrow`). Text-control focus uses `--ring` (= primary in light, coral in `.theme-dark`) with 3 px ring/25%; disabled text fields = muted bg + 60% text (CMP-FORM-01), other controls 50% opacity. `text-overline` (12 px) is the only text under 13 px. Button keeps an extra `destructive` variant for the admin. Why: spec silent on dark hovers/badge colour utilities; consistent focus colour per scope.
- **DEC-37 (2026-10-25, 0.3) — Number/date formatting conventions.** Compact BDT uses `৳` per ARC-017 (`৳ 1.45 crore`), superseding the glossary's `Tk 1.25 crore`. A non-breaking space follows `৳` and precedes units. Compact: < 1 lakh full form, 2 decimals max, trailing zeros trimmed, 99,99,999 → `৳ 1 crore`. Ranges: `1,650–2,100 sft`, `৳ 85–95 lakh` (same unit), `৳ 85 lakh – 1.45 crore` (mixed). Grouping is hand-written in both twins (no Intl/`intl` ext) so PHP, SSR and browsers agree. Why: spec silent beyond the examples; no wrapped `৳`/units.
- **DEC-38 (2026-10-25, 0.3) — Demo image pipeline details.** Owner chose generated labelled placeholders until client photos arrive (replace per group, edit `meta.json`, re-run). Content hash sits in the folder name (`/demo/{group}/{slug}-{hash}/{conversion}.{ext}`), which satisfies CMS-MED-011 caching. `thumb` also gets AVIF. `MediaImage` adds `caption`, `credit`, `sources.jpeg`; OG URL comes separately (`DemoMedia::ogImage`). `public/demo` and `storage/app/demo-src` are not committed; deploys run `php artisan demo:images --placeholders`.
